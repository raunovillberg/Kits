# 2026-02-06 – Kits

## Switched settings persistence from UserDefaults to JSON file

- Replaced `UserDefaults`-based settings persistence with a versioned JSON file store.
- Default settings file path is now:
  - `~/.kits/settings.json`
- Added `JSONSettingsStore` with atomic writes and automatic directory creation.
- Added `SettingsSnapshot` (Codable) with explicit `version` field for future migrations.
- Current settings schema version is `1`.
- `Settings` now persists all previously UserDefaults-backed fields into the JSON snapshot:
  - `rootFolderPath`
  - `sortMode`
  - `clickAction`
  - `customCommand`
  - `popoverWidth`
  - `popoverHeight`
  - `uiScale`

## Testability updates

- Replaced `UserDefaultsProtocol` with `SettingsStoreProtocol`.
- Added `MockSettingsStore` for unit tests.
- Updated `SettingsTests` and `GitScannerTests` to inject `SettingsStoreProtocol`.

## Notes

- No migration from old `UserDefaults` values was implemented by design (pre-public app).
- Settings file is written on initialization as well, so the file/version exists even before user changes settings.
- Added explicit migration scaffolding in `Settings`:
  - `migrateSnapshotIfNeeded`
  - `migrate(snapshot:to:)`
  - `migrateV0ToV1`
- Added a unit test to verify that version `0` snapshots get migrated to version `1` on initialization.

## Repository refresh optimization: discovery cache + unavailable repos

- Added a new persisted discovery cache file next to settings:
  - `~/.kits/directories.json`
- Added `DirectorySnapshot` + `DirectoryStoreProtocol` + `JSONDirectoryStore`.
- `GitScanner` now separates scan phases:
  1. **Discovery** (recursive folder traversal) is reused from cache by default.
  2. **Status refresh** runs on the cached repository paths.
- Discovery is now force-refreshed when root folder changes (`rootFolderPathPublisher` path change flow), then persisted back to `directories.json`.
- On normal timer/manual refreshes, scanner skips re-discovery when cache matches current root.
- Added handling for deleted/missing repositories:
  - `GitRepository` now has `isAvailable` flag (default `true`).
  - Missing cached repo paths are surfaced as unavailable entries (`isAvailable = false`) instead of disappearing.
  - UI rows are disabled + greyed out for unavailable repos and won’t trigger open action.
- Additional status-refresh performance work after observing ~11s scans with cached discovery:
  - Capped concurrent repo scans with `Constants.Scanning.maxConcurrentGitOperations`.
  - Removed duplicate `git log` call in `getLastFileModification` (now uses already-fetched current-branch commit date fallback).
  - Reused cached `gitCommonDir` to avoid repeated `git rev-parse --git-common-dir` per refresh.
  - Only refreshes any-branch commit timestamp when needed (`sortMode == .anyBranchCommit` or cache empty).
  - Added scan phase timing logs: total + resolve + status durations and discovery cache hit/miss state.
- Added persisted repository status cache for instant startup UX:
  - New file: `~/.kits/repositories.json`.
  - Added `RepositorySnapshot` + `RepositoryStoreProtocol` + `JSONRepositoryStore`.
  - `GitScanner.startScanning()` now preloads cached repositories synchronously (if root matches), so list appears immediately on app launch.
  - Scanner then performs normal async refresh and overwrites cache after successful scan.
  - Added UI-visible stale-data indicator state (`isShowingCachedSnapshot`) so header can say e.g. "Showing cached data, updating..." while refresh is in progress.
- Updated tests:
  - `testPerformScan_UsesCachedDiscoveryWhenAvailable`
  - `testScanRepository_MissingRepositoryIsMarkedUnavailable`
  - Added `MockDirectoryStore`.
